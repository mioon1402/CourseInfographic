| `notebooks/*.ipynb` | 분석별 **실행용 노트북** 30개 (각 5KB). 분석 15종 × (내 파일용 / 예제 데이터용) |

페이지는 세 갈래입니다. **홈(index.html)** 에서 “처음이라 배우고 싶다 / 목표는 있는데 방법을 모르겠다 /
바로 분석하겠다” 중 하나를 고르면 각각 **배우기 · 질문 만들기 · 분석하기** 로 갑니다.
교육 페이지의 강의마다 “바로 해보기” 링크가 있어 **읽은 개념을 그 자리에서 실습**할 수 있습니다.
(`portal.html?mod=분석코드&demo=1` 형태로 분석이 미리 선택된 채 열립니다)

동작 방식은 이렇습니다. 포털에서 분석을 고르면 **그 분석 전용 노트북**이 Colab에서 열리고,
노트북은 `dap_engine.py` 를 내려받아 **고른 분석 하나만** 실행합니다.

### 왜 엔진과 노트북을 나눴나

처음에는 모든 분석 코드를 노트북 하나(224KB, 셀 15개)에 담았는데, 세 가지 문제가 있었습니다.

* **느렸습니다** — 어떤 분석을 하든 12개 모듈 코드를 전부 로드하고 안 쓰는 라이브러리까지 확인했습니다.
* **매번 처음부터 실행해야 했습니다** — 분석 종류가 노트북 안의 변수라 모든 분석이 같은 파일을 공유했습니다.
* **설정 코드를 붙여넣어야 했습니다** — 초보자에게 가장 큰 벽이었습니다.

지금 구조에서는 노트북이 **5KB / 셀 3개**로 줄었고, 고른 분석에 필요한 라이브러리만 설치하며,
컬럼은 **드롭다운으로** 고릅니다. 설정을 바꿀 때는 **3단계 셀만 다시 실행**하면 되고
파일을 다시 올릴 필요가 없습니다.

### ② 노트북 위치 — 자동으로 찾습니다

포털은 `candidates` 에 적힌 브랜치를 앞에서부터 확인해서 **파일이 실제로 있는
브랜치를 스스로 찾아 씁니다.** 브랜치를 손으로 고칠 필요가 없고, 작업 브랜치를
`main` 에 머지하면 다음 접속부터 알아서 `main` 을 사용합니다.

```javascript
const NB = {
  owner: 'mioon1402',
  repo:  'CourseInfographic',
  pathFor: (id, demo) => `notebooks/${id}${demo ? '__demo' : ''}.ipynb`,
  probe:   'dap_engine.py',                  // 브랜치 확인용
  candidates: ['main', 'claude/all-in-one-data-analysis-portal-t73xwf'],
  ...
};
```

노트북 안에도 같은 후보 목록이 들어 있어(`ENGINE_URLS`), 엔진을 어느 브랜치에서
가져올지 스스로 찾습니다.

확인 결과는 실행 요약 패널 아래에 `✔ 노트북 확인됨 · main` 처럼 표시되고,
브라우저에 6시간 동안 기억됩니다.

* **다른 저장소로 옮겼다면** `owner` / `repo` 만 고치세요.
* **특정 브랜치를 강제하려면** 주소 뒤에 `?nb_branch=브랜치이름` 을 붙이세요.
  (예: `.../portal.html?nb_branch=dev`) — 이 값이 항상 우선합니다.
* 정리가 끝나 작업 브랜치를 지웠다면 `candidates` 에서 그 이름을 빼도 됩니다.
  (남겨 둬도 `main` 을 먼저 찾으므로 문제 없습니다)

## 2. 동료가 사용하는 방법 (3단계)

1. **포털에서 분석 카드를 고릅니다.** 용어를 몰라도 각 카드에 적힌
   *“다음 달 판매량은 얼마나 될까?”* 같은 질문 문장을 보고 고르면 됩니다.
2. **컬럼과 옵션을 지정합니다.** CSV 파일을 포털에 끌어다 놓으면 컬럼 이름이
   **드롭다운 목록**으로 바뀌어 오타 걱정이 사라집니다.
   *(이때 파일은 어디에도 전송되지 않습니다. 브라우저 안에서 첫 몇 줄만 읽습니다.)*
3. **[Colab에서 분석 시작]** 을 누릅니다. **고른 분석 전용 노트북**이 열립니다.
   상단 메뉴 **[런타임] → [모두 실행]** (`Ctrl`+`F9`) 을 누르고, 파일 선택 창이 뜨면 CSV를 올립니다.
   컬럼은 **드롭다운으로 고르면 되고, 타이핑할 것은 없습니다.**

> 🔁 **결과를 보고 컬럼을 바꾸고 싶다면** 노트북 2단계의 드롭다운만 바꾸고
> **3단계 셀만 다시 실행**하세요. 파일을 다시 올리거나 처음부터 실행할 필요가 없습니다.

끝나면 그래프와 해석이 화면에 나오고, **HTML 리포트 + 결과 CSV** 가 ZIP으로 자동 다운로드됩니다.
HTML 리포트는 **인터넷 없이도 열리고 그래프도 그대로 움직이므로** 동료에게 그냥 보내면 됩니다.

> 🧪 **연습해 보고 싶다면** 포털 STEP 2의 **[🧪 예제 데이터로 연습]** 을 누르세요.
> Colab이 예제를 직접 만들어 내므로 **파일을 올릴 필요가 없습니다.**
> (노트북 2단계의 `데이터_가져오기` 드롭다운에서 바꿀 수도 있습니다)

### ❓ 왜 Colab에서 파일을 한 번 더 올려야 하나요?

포털은 **내 컴퓨터의 브라우저**에서 돌고, Colab은 **구글 서버**에서 돕니다. 서로 다른 곳입니다.
포털이 올린 파일을 읽는 것은 컬럼 이름을 알아내기 위해서일 뿐이고, 그 파일은 **어디에도
전송되지 않습니다.** 자동으로 넘기려면 데이터를 외부 서버에 올려야 하는데, 사내 데이터를
다루는 도구에서는 그러지 않는 편이 안전하다고 판단했습니다.

* **예제 데이터**는 코드로 만들어 내는 것이라 업로드가 아예 필요 없습니다.
  포털에서 예제를 고르면 `notebooks/<분석>__demo.ipynb` (예제 전용 노트북)로 연결됩니다.
  “예제로 연습”이라는 신호를 URL 로 보내면 Colab 이 못 읽는 경우가 있어, 아예 **다른 노트북**으로
  연결해 전달 실패 자체가 생기지 않게 했습니다.
* **내 파일**은 Colab에서 같은 파일을 한 번 더 선택해 주셔야 합니다.
  (파일 선택 창에서 그대로 고르시면 됩니다)

## 3. 지원하는 분석 (15종)

| 카테고리 | 분석 | `module_id` | 필요한 것 |
|---|---|---|---|
| 데이터 준비 | 여러 파일 합치기 | `data_merge` | CSV 2개 이상 |
| 데이터 준비 | 컬럼 정의·단위 일관성 점검 | `definition_check` | 숫자 컬럼 |
| 탐색적 분석 | 데이터 자동 요약 리포트 | `eda_summary` | — |
| 탐색적 분석 | 데이터 품질 진단 및 자동 정제 | `data_quality` | — |
| 탐색적 분석 | 다중 변수 상관관계 (Heatmap) | `eda_corr` | 숫자 컬럼 2개 이상 |
| 비교·검정 | 그룹 간 차이 비교 (통계 검정) | `compare_groups` | 그룹 + 숫자 컬럼 |
| 비교·검정 | 교란변수 점검 & 층화 비교 | `confound_check` | 그룹 + 숫자 컬럼 |
| 시계열 분석 | 미래 추세·계절성 예측 (Prophet) | `ts_forecast` | 날짜 + 타겟 컬럼 |
| 시계열 분석 | 평활화 및 트렌드 추출 (STL) | `ts_smooth` | 날짜 + 타겟 컬럼 |
| 이상 탐지 | 스파이크·불량 감지 (Isolation Forest) | `anomaly_iforest` | 숫자 컬럼 |
| 품질관리 | 공정 관리도 (SPC) | `spc_control` | 측정값(숫자) 컬럼 |
| 품질관리 | 파레토 분석 (80/20) | `pareto` | 분류 컬럼 |
| 수치 예측 | 결과 수치 예측 (Random Forest) | `regress_rf` | 타겟(숫자) 컬럼 |
| 상태 분류 | 정상/불량 분류 (XGBoost) | `classify_xgb` | 타겟(범주) 컬럼 |
| 군집화 | 유사 데이터 그룹핑 (K-Means) | `cluster_kmeans` | 숫자 컬럼 2개 이상 |

모든 결과에는 **“🧭 이 결과를 이렇게 읽으세요”** 해석 상자가 붙습니다.
숫자를 그대로 던지지 않고, *“실제 불량 100건 중 87건을 잡아내고 13건을 놓칩니다”* 처럼
현업 언어로 풀어서 설명합니다.

### 잘못 쓰기 쉬운 분석은 경고해 드립니다

예를 들어 **공정 관리도(SPC)** 에 매출·생산량처럼 계속 늘어나는 값을 넣으면 거의 모든 점이
“이상”으로 표시됩니다. 관리도는 *“공정이 일정한 수준을 유지한다”* 는 전제 위에서만 뜻이 있기
때문입니다. 이런 경우 결과를 그대로 내놓지 않고, **왜 맞지 않는지와 무엇을 대신 하면 되는지**를
먼저 알려 드립니다.

### 분석 기법 밖의 문제도 다룹니다

데이터 분석에서 어려운 부분은 계산이 아니라 그 앞뒤입니다. 이 포털이 다루는 범위는 이렇습니다.

| 실무의 어려움 | 이 포털의 대응 | 한계 |
|---|---|---|
| **무엇을 물어볼지 모르겠다** | 🧭 **질문 만들기 마법사** — 목표를 3번 클릭으로 답할 수 있는 질문으로 바꾸고, 분석 순서를 제안 | 무엇이 중요한지는 정해 주지 못합니다 |
| **자료가 흩어져 있다** | 🧬 **여러 파일 합치기** — 연결 키 자동 탐색, 일치율 진단, 시간 단위 맞추기 | 컬럼 이름 자체가 다르면 먼저 맞춰야 합니다 |
| **숫자의 뜻이 맞는지 모르겠다** | 🔍 **정의·단위 일관성 점검** — 그룹·기간별 스케일 차이, 기준 변화를 찾아 확인 질문 생성 | 숫자로 드러나는 단서만 봅니다 |
| **상관이지 인과인지 모르겠다** | 🔀 **교란변수 점검 & 층화 비교** + 🧪 **A/B 설계 계산기** | 기록되지 않은 요인은 알 수 없습니다 |

**의도적으로 넣지 않은 것**: 텍스트·이미지 분석, 사내 DB 직접 연결, 모델 상시 운영(배포).
비개발자가 클릭으로 다루기에 위험하거나(DB 접근 권한), 별도 환경이 필요한 영역이라 범위 밖으로 두었습니다.

## 3-2. 교육 페이지 (`learn.html`)

분석 기법 설명서가 아니라 **데이터를 읽는 눈**을 기르는 것이 목적입니다.
실무에서 실제로 오판이 나오는 지점만 골랐고, **비전공자가 읽어도 이해되는 말**로 쓰되

### 6장 — 수학 트랙 (14편)

“왜 그런가”를 묻는 사람을 위한 장입니다. **건너뛰어도 나머지를 이해하는 데 지장이 없다**고
페이지에 명시해 두었고, 각 강의는 늘 같은 순서로 씁니다 —
**직관 → 수식 → 기호 하나하나 풀이 → 왜 이렇게 되는가 → 실무에서 어디에 쓰이는가.**

1. 수식 읽는 법 (Σ · 첨자 · 바 표기)
2. 평균 · 분산 · 표준편차 — **왜 n이 아니라 n−1로 나누는가**
3. 정규분포와 z점수
4. 중심극한정리와 표준오차 σ/√n — **왜 정밀도를 2배 하려면 데이터가 4배 필요한가**
5. 신뢰구간
6. 가설검정 — t통계량 · p값 · 검정력 · 필요 표본 수 공식
7. 공분산과 상관계수 — **r = cos θ 인 이유**
8. 최소제곱 회귀 — β̂ = (XᵀX)⁻¹Xᵀy 와 R²
9. 분류 — 로그 오즈 · 시그모이드 · 교차엔트로피 · 혼동행렬
10. 트리와 앙상블 — 지니 · 엔트로피 · 정보이득 · 배깅 vs 부스팅
11. 거리와 군집 — K-means 목적함수 · 실루엣
12. 시계열 — 가법분해 · ACF · Prophet(g+s+h+ε) · MAPE
13. 공정능력 Cp · Cpk 유도
14. 편향–분산 분해 — 과적합의 정체

> 수식은 **KaTeX·MathJax 같은 외부 라이브러리를 쓰지 않고** 유니코드로 직접 그렸습니다.
> CDN이 막힌 사내망이나 오프라인에서도 항상 보이게 하기 위해서입니다.

## 5. 새 분석 모듈 추가하기 (개발자용)

세 군데만 고치면 됩니다.

**① `portal.html` 의 `MODULES` 배열에 항목 추가**

```javascript
{
  id:'my_module', cat:'eda', icon:'🧮',
  name:'내 새 분석',
  desc:'무엇을 해주는지 한 줄 설명',
  q:'“어떤 질문에 답하나요?”',
  level:'입문', time:'약 1분',
  about:'이 분석이 무엇을 해주는지 두세 문장으로',
  dataNeed:'어떤 컬럼이 필요한지',
  outputs:['나오는 결과물 1','나오는 결과물 2'],
  need:{ date:'none', target:'required', group:'none', features:'optional' },
  params:[
    { key:'my_param', label:'옵션 이름', type:'number', def:10, min:1, max:100, step:1,
      help:'비개발자가 읽고 이해할 수 있는 설명' }
  ]
}
```

* `need` 의 네 칸(`date` · `target` · `group` · `features`)에 `required` / `optional` / `none`
  을 적으면 STEP 3 입력란이 자동으로 만들어집니다.
* `params` 의 `type` 은 `number` · `select` · `bool` · `text` 를 지원하고,
  앞의 3개는 기본 화면에, 나머지는 **“세부 옵션 더 보기”** 안에 자동으로 들어갑니다.
* `about` / `dataNeed` / `outputs` / `time` / `level` 은 카드를 눌렀을 때 나오는
  **상세 설명 패널**에 그대로 표시됩니다.
* 도움말 문장에 `GLOSSARY` 에 등록된 용어가 들어 있으면 **자동으로 툴팁**이 붙습니다.
  새 용어를 쓰신다면 `GLOSSARY` 에 한 줄 추가해 주세요.

**② `dap_engine.py` 에 함수 추가 + 목록 3곳에 등록**

```python
def run_my_module():
    h_title("🧮 내 새 분석")
    value = P_int("my_param", 10)        # 포털에서 보낸 옵션 읽기
    col   = resolve_col(TARGET_COL, kind="number", required=True)
    ...
    show(fig)                            # 그래프 출력 + 리포트에 자동 수록
    h_insight(["해석 문장 1", "해석 문장 2"])
    RESULT_FILES.append(("결과.csv", result_df))
```

같은 파일 위쪽의 목록 세 군데에 한 줄씩 추가합니다.

```python
MODULE_CATALOG = [ ..., ("my_module", "내 새 분석", "한 줄 설명") ]

MODULE_NEEDS["my_module"] = {"date":"none", "target":"required",
                             "group":"none", "features":"optional"}

# 추가 라이브러리가 필요할 때만
MODULE_DEPS["my_module"] = [("mlxtend", "mlxtend", "mlxtend")]
```

그리고 `run_module()` 안의 라우터에 한 줄:

```python
elif MODULE_ID == "my_module":
    RESULT = run_my_module()
```

**③ 실행용 노트북 만들기**

`notebooks/my_module.ipynb` 와 `notebooks/my_module__demo.ipynb` 를 기존 것에서
복사해 만들고, 1단계 셀의 `dap.bootstrap("...")` 안 이름만 바꾸면 됩니다.
(노트북에는 분석 코드가 없어 사실상 이름만 다릅니다. `__demo` 쪽은 2단계
`데이터_가져오기` 기본값이 **예제 데이터로 연습** 으로 되어 있습니다)

사용 가능한 도구:

| 도구 | 역할 |
|---|---|
| `h_title` / `h_sub` | 제목 (자동으로 리포트 목차에 등록됩니다) |
| `h_metrics([(제목,값,설명)…])` | 핵심 숫자 타일 한 줄 |
| `h_note(문장, "info\|good\|warn\|crit")` | 색깔 있는 안내 상자 |
| `h_insight([문장…])` | “🧭 이 결과를 이렇게 읽으세요” 해석 상자 |
| `h_table(df, 설명)` | 보기 좋은 표 |
| `show(fig)` | 그래프 출력 + 리포트에 자동 수록 |
| `P_int` / `P_float` / `P_bool` / `P_str` / `P_list` | 포털이 보낸 파라미터 읽기 |
| `resolve_col(이름, kind=, required=)` | 컬럼 이름 자동 보정 (오타·대소문자·유사 이름) |
| `pick_features(exclude=)` | 분석에 쓸 컬럼 자동 선택 |
| `DATE_COL` / `TARGET_COL` / `GROUP_COL` / `FEATURE_COLS` | 사용자가 지정한 컬럼 |
| `PALETTE` / `SEQ_BLUE` / `DIVERGING` | 색약 검증을 통과한 색상 팔레트 |
| `RESULT_FILES.append((파일명, df))` | 결과 CSV 함께 저장 |

> ⚠️ 리포트 HTML을 직접 작성할 때 폰트 이름은 **작은따옴표**로 감싸세요.
> 큰따옴표를 쓰면 `style="..."` 속성이 중간에 끊겨 디자인이 통째로 깨집니다.
